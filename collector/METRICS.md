# 단위경제 입력값 ← 수집 이벤트 대응표

`events` 시트의 열은 A~U 순서다.
A t · B vid · C sid · D ev · E dev · F role · G src · H screen · I act · J target · K intent · L reward · M withdraw · N secs · O form · P tx · Q grade · R gender · S org · T exp · U name

아래 수식은 **아직 실제 시트에서 돌려 보지 않았다.** 처음 쓸 때 몇 줄만 손으로 세어 값이 맞는지 확인한다.
N열(secs)이 숫자가 아니라 글자로 들어갔으면(셀이 왼쪽 정렬이면 글자) `MEDIAN` 이 오류를 내므로 `VALUE()` 로 감싼다.

## 먼저 할 일

1. 테스트 행을 뺀다. `src` 가 `claudetest` 인 행과 팀원이 시험 삼아 넣은 행은 계산에서 제외한다(수식에 `G2:G<>"claudetest"` 조건을 더하거나 별도 탭으로 옮긴다). 2026-11-06에 그때까지의 `claudetest` 행(배포 점검 4행, 동시 접속 시험 2,669행)을 모두 지웠다. 앞으로도 시험 행은 `src=claudetest` 로 넣고, 다 쓴 뒤 Apps Script 편집기에서 `clearTestRows` 를 실행해 지운다. 2026-11-04 이전의 시험 기록은 `events_old_1104` 탭에 그대로 남겨 두었다.
2. 동아리별로 나누려면 배포 주소에 `?src=club-이름` 을 붙여 나눠 준다(예: `…/?src=club-photo`). `src` 열에 그대로 남는다.
3. 표본이 작으면 비율은 크게 흔들린다. 응답 30명이면 ±18%p, 100명이면 ±10%p 정도다. 비율을 보고서에 쓸 때는 "n=○○"를 같이 적는다.

## 입력값별 대응

| 모델 입력(v51) | 어디서 재나 | 계산 |
|---|---|---|
| 월 활성 부원 비율 52% | `page_view` 를 남긴 role=member 방문자(vid) ÷ 동아리 부원 수 | 부원 수는 앱 밖(총무에게 확인)에서 받아야 한다. 앱은 명단을 모른다 |
| 활성 부원 월 세션 2회 / 운영진 월 세션 12 | 방문자별 서로 다른 sid 수, role별 | `=COUNTUNIQUE(FILTER(C2:C, F2:F="member"))/COUNTUNIQUE(FILTER(B2:B, F2:F="member"))`. 기간이 한 달보다 짧으면 달 환산이 필요하다 |
| 세션당 광고 노출 1.5 | `ad_view` 행 수 ÷ 서로 다른 sid 수 | `=COUNTIF(D2:D,"ad_view")/COUNTUNIQUE(C2:C)`. 배너가 4장 돌아가므로 한 화면에서 최대 4번까지 센다(배너마다 화면당 한 번, 멈춰서 보인 것만). 모델의 1.5와 비교할 때는 이 점을 감안한다 |
| 광고 클릭률 0.3% | 배너 클릭 ÷ `ad_view`, 배너(target)별로도. 클릭은 2026-11-06부터 `ad_click`, 그 전에는 `ui_click`(act=`ad`)으로 남았다 | 전체 `=(COUNTIF(D2:D,"ad_click")+COUNTIFS(D2:D,"ui_click",I2:I,"ad"))/COUNTIF(D2:D,"ad_view")`, 배너별은 `J2:J="kb-insurance"` 처럼 target 조건을 세 곳에 모두 더한다. 배너 키: `kb-insurance`, `oliveyoung-sale`, `baemin-isaac-toast`, `spotify-afterparty` |
| 설문 소요 10분 | form=`survey:done` 행의 secs 중앙값 | `=MEDIAN(FILTER(N2:N, O2:O="survey:done"))` (초 단위). 샘플 설문이 15문항 약 5분짜리라 실제 일감의 10분과는 다르다 |
| 설문 완료율·이탈 구간 | form=`survey:A`~`E`, `done`, `out`, `quit-X` | 구간별 서로 다른 vid 수를 세어 A→B→…→done 으로 나눈다. `out` 은 대상 아님(1번 문항에서 탈락), `quit-X` 는 X구간에서 닫음 |
| 설문·일감 가입률 50% | perk_answer, target=`job-survey` 의 intent=yes 비율 | `=COUNTIFS(D2:D,"perk_answer",J2:J,"job-survey",K2:K,"yes")/COUNTIFS(D2:D,"perk_answer",J2:J,"job-survey")`. 말로 한 의향이라 실제보다 높게 나오기 쉽다 |
| 일감 참여 비율(UT·데이터·AI평가) | target=`job-ut` / `job-photo` / `job-eval` 의 intent=yes 비율 | 위와 같은 식에서 target만 바꾼다 |
| 일감 최소 보상(할 만한 금액) | 같은 target의 reward(원) 중앙값 | `=MEDIAN(FILTER(L2:L, D2:D="perk_answer", J2:J="job-ut"))` |
| 최소 인출 5,000원 | 첫 일감 답변의 withdraw(원) | `=MEDIAN(FILTER(M2:M, D2:D="perk_answer", LEFT(J2:J,4)="job-"))` |
| 쿠폰 사용률 1% | target=`food-*` 의 intent=yes 비율, reward(최소 할인 %) | 말로 한 의향이라 실제 사용률과는 다르다. 실제 사용률은 쿠폰을 실제로 발급해 봐야 안다 |
| 제휴 결제 비중 20% | target=`tr-pay` 의 reward(연 지출 중 %) 중앙값 | role=treasurer 답변만 들어온다 |
| 이동 행사 2회/년·18명 | target=`tr-insurance` 의 reward(명), withdraw(회) 중앙값 | 둘째 질문(연 몇 회)은 withdraw 열에 들어간다 |
| 통계 활용 동의율 70% | target=`tr-data` 의 intent=yes / maybe / no 비율 | 보고서에는 yes 만이 아니라 maybe 를 따로 적는다 |
| 방문 한 번의 체류 시간 | `session_time` 행의 secs. 같은 sid 안에서는 가장 큰 값 | `=QUERY(A:U,"select C, max(N) where D='session_time' group by C",1)` 결과의 평균·중앙값 |
| 화면별 머문 시간 | `screen_time` 의 secs | screen별 평균·중앙값. 한 사람의 탭별 시간은 아래 "한 사람의 탭별 체류 시간" |
| 가입(참여 정보 입력) 전환 | profile 행이 있는 vid ÷ **GA4 사용자 수** | 앱은 참여 정보를 입력하기 전의 기록을 메모리에만 두고 시트로 보내지 않는다. 그래서 시트에는 입력을 마친 사람만 있고, 시트 안에서만 나누면 늘 100%가 된다. 입력 창에서 나간 사람은 GA4에만 남으므로 분모는 GA4에서 가져온다(대시보드의 노란 칸) |

## 대시보드 탭(시트 1면)

위 표의 값을 손으로 수식을 넣지 않고 한 장에서 보려면 `Dashboard.gs` 를 쓴다. 아직 실제 시트에서 돌려 보지 않았다(가짜 시트 위에서 끝까지 돌아가는지와 수식 237개의 괄호·따옴표 짝만 확인했다).

1. 수집기를 붙인 같은 Apps Script 프로젝트에 파일(+) > 스크립트로 `Dashboard` 를 만들고 `Dashboard.gs` 내용을 붙여 넣는다.
2. 함수 `대시보드만들기` 를 한 번 실행한다. 맨 앞에 `대시보드` 탭이, 숨김으로 `_data` 탭(events 에서 시험용 src 를 뺀 사본, 이름 열 없음)이 생긴다. 시트를 다시 열면 `QFlowz > 대시보드 새로 만들기` 메뉴가 생긴다.
3. 수집기 웹 앱은 다시 배포하지 않아도 된다. 숫자는 모두 수식이라 기록이 쌓이면 저절로 바뀐다. 스크립트를 다시 돌리는 것은 대시보드 모양을 바꿨을 때뿐이다.
4. 노란 칸은 직접 고친다: 제외할 src(기본 `claudetest`), GA4 사용자 수(가입 전환의 분모), 비교에 필요한 최소 표본(기본 10), 모델 가정 값. 다시 만들어도 이름표가 같으면 값이 그대로 옮겨진다.

담긴 것: 한눈에 보기 카드 10개 → 차트 3개(설문 단계별 도달, 배너별 클릭률, 혜택 질문별 쓸 의향) → 모델 가정 vs 실측 표(가정의 ±10% 안이면 "비슷", n이 최소 표본보다 작으면 "표본 적음") → 혜택 질문 항목별 응답 → 샘플 설문 단계 → 배너별 → 유입 경로별 → 표본 구성 → 잴 수 없는 것 → 데이터 점검(열 순서, 숫자가 글자로 들어갔는지, 마지막 기록) → 화면별 머문 시간.

배너 클릭은 `ad_click`(2026-11-06부터)과 예전 `ui_click`(act=`ad`)을 더해 센다. 한 클릭은 둘 중 하나로만 남는다. 수집기는 2026-11-06 0시 28분에 `ad_click` 을 받는 버전 3으로 배포했다. 앱이 `ad_click` 을 보내는 것은 앱 변경이 main에 합쳐져 사이트에 배포된 뒤부터다.

처음 열었을 때 맨 위 "데이터 점검"이 정상인지 먼저 보고, events 에서 몇 줄을 손으로 세어 카드 숫자와 맞는지 확인한다.
`Code.gs` 의 열 배열을 바꾸면 `Dashboard.gs` 의 `기대열` 도 같이 고친다.

## 한 사람의 탭별 체류 시간

`screen_time` 행에 방문자 코드(vid)와 화면(screen)과 머문 초(secs)가 남으므로 가능하다. 화면 이름은 `m/ledger`(부원 거래 내역), `t/perks`(총무 혜택) 처럼 역할/탭이다.
이름은 참여 정보를 입력할 때 한 번 남는 `profile` 행(U열)에만 있으니, 이름으로 vid 를 찾은 뒤 그 vid 의 `screen_time` 을 합친다. 수식은 아직 실제 시트에서 돌려 보지 않았다.

1. 새 탭을 만들어 A1 에 찾을 이름을 적는다.
2. vid 찾기: `=INDEX(events!B2:B, MATCH(A1, events!U2:U, 0))` 를 B1 에 둔다.
3. 탭별 합계: `=QUERY(events!A:U, "select H, sum(N), count(N) where D='screen_time' and B='"&B1&"' group by H order by sum(N) desc label sum(N) '합계(초)', count(N) '횟수'", 1)`
4. 모든 사람을 한 표로: `=QUERY(events!A:U, "select B, sum(N) where D='screen_time' group by B pivot H", 1)` (행은 vid, 열은 화면)

알아 둘 점
- 시간은 탭이 화면에 보이는 동안만 센다. 다른 탭으로 가거나 화면이 꺼진 시간은 빠진다. 한 번에 최대 30분까지만 인정한다.
- vid 는 브라우저마다 따로 생기므로 같은 사람이 폰과 노트북을 쓰면 vid 가 둘이다. 이름으로 합친다.
- 이름은 새 `Code.gs` 를 배포한 뒤(2026-11-04 오후 10시 버전 2)에 입력한 사람부터만 저장된다. 그 전에 들어온 행에는 이름이 없다.
- 이 표에는 이름이 들어가므로 보고서에는 이름을 빼고 vid 나 "참여자 A" 같은 이름표로 바꿔 옮긴다.

## 광고 클릭률을 읽을 때

- 배너에는 "광고 자리 예시 · 실제 광고 아님"이 붙어 있고, 눌러도 어디로도 연결되지 않는다(토스트만 뜬다). 그래서 이 숫자는 실제 광고의 클릭률이 아니라 **"예시라고 알려 줬는데도 누른 사람의 비율"** 이다. 모델의 0.3%에 그대로 넣지 말고, 배너끼리 비교(어떤 소재가 더 눈길을 끄나)와 위치별 비교에 쓴다.
- 배너는 자동으로 5초마다 넘어가므로 노출 수는 "띠가 화면에 절반 이상 보이고, 배너가 멈춰 있을 때"만 센다. 지나가기만 한 배너, 탭이 가려진 동안의 배너는 세지 않는다.
- 배너 이미지의 광고주(KB손해보험·올리브영·배달의민족·이삭토스트·스포티파이)와 모델 얼굴은 실제 업체·인물의 것이다. 수업용 비공개 시연에서만 쓰고, 공개 배포 전에는 직접 만든 이미지로 바꾸거나 사용 허락을 받는다.

## 여러 명이 동시에 보낼 때(2026-11-06 시험)

실제 수집 주소로 가짜 방문자를 동시에 보내 시험했다. 시험 행은 끝난 뒤 모두 지웠다.

| 시험 | 고치기 전(수집기 버전 2, 5초마다 보냄) | 고친 뒤(버전 3, 20초마다 + 재시도) |
|---|---|---|
| 30명이 동시에 한 번 | 600행 중 360행만 남음 | 600행 모두, 한 번씩 |
| 60명이 동시에 한 번 | 하지 않음 | 600행 모두. 늦은 것은 1분 45초 뒤에 들어옴 |
| 30명이 계속 사용(4~5회) | 750행 중 455행만 남음 | 600행 모두, 한 번씩 |

- 수집기는 시트에 한 번 쓰는 데 0.5초 남짓 걸리고 한 번에 하나씩만 쓴다. 초당 1.5건 안팎이 한계다.
- 고치기 전에는 두 가지 이유로 기록이 조용히 빠졌다. 10초 안에 차례가 오지 않으면 거절했는데 앱이 다시 보내지 않았다. 잠금을 풀기 전에 시트에 확정하지 않아, 다음 요청이 같은 줄을 덮어쓴 경우도 있었다('받았다'고 답한 묶음 121개 중 2개).
- 지금은 수집기가 30초까지 기다리고, 시트에 확정한 뒤 잠금을 푼다. 앱은 20초마다(또는 30개가 쌓이면, 화면을 닫거나 가릴 때) 묶어 보내고, 'ok'를 받지 못하면 5·10·20…초, 최대 1분 간격으로 같은 묶음을 다시 보낸다. 보내지 못한 묶음은 브라우저(localStorage)에 남겼다가 다음 방문 때 보낸다.
- 수집기는 같은 묶음 이름표(bid)를 6시간 동안 한 번만 쓴다. 시험 중 응답이 늦어 다시 보낸 묶음도 한 번만 들어갔다.
- 그래서 많이 몰리면 기록이 늦게 들어올 뿐 빠지지 않는다(60명이 동시에 열면 1~2분). 다만 화면을 닫은 뒤 다시 오지 않는 사람의, 닫을 때 보낸 마지막 묶음까지 거절되면 그 묶음은 빠진다.
- 시트의 행 순서는 도착 순서라 여러 사람의 행이 섞인다. 사람별로 볼 때는 vid로 거르고 t로 정렬한다. t는 각자 기기의 시계다.
- GA4는 구글 서버가 따로 받으므로 이 문제와 상관없다.
- 2026-11-06 이전 기록(실제 이용자 201행)은 몰림이 적은 때라 크게 빠지지 않았을 것으로 보지만, 빠진 행은 흔적이 남지 않아 확인할 수 없다.

## 이 테스트로는 잴 수 없는 것

- **학기 유지율 70%** — 한 학기 동안 같은 사람이 남아 있는지는 학기가 끝나야 안다. 지금은 첫 주와 마지막 주에 다시 온 vid 비율 정도만 대신 볼 수 있다. 대시보드의 "재방문율" 카드는 서로 다른 sid 가 2개 이상인 vid ÷ 전체 vid 이다. sid 는 브라우저 탭마다 새로 생기므로 같은 날 탭을 두 개 연 것도 재방문으로 잡힌다.
- **가입자 중 월 응답 10%** — 매달 반복해서 응답한 비율이라 한 번 하는 테스트로는 나오지 않는다.
- **실제 결제·실제 쿠폰 사용·실제 광고 매출** — 목업이라 말한 의향만 있다. 의향은 실제보다 높게 나오는 경향이 있으니 모델에 넣을 때 보수적으로 깎아 쓰고, 깎은 근거를 같이 적는다.
- **CAC 단계별 전환(40/46/36%)** — 광고 집행 전이라 비어 있다. 유입 경로(src)별 가입 전환까지만 볼 수 있다.

## 시트 관리 주의

- 이 시트에는 이름이 들어 있다. 팀원에게만 공유하고, 보고서나 발표 자료에는 이름 열을 빼고 옮긴다.
- 삭제를 요청받으면 그 사람의 vid 를 찾아(U열 이름으로 B열 확인) 같은 vid 의 모든 행을 지운다. 문의 연락처가 앱에 아직 비어 있으니(`CONFIG.privacy.contact`) 공개 전에 채운다.
- Code.gs 를 고치면 새 버전으로 다시 배포해야 반영된다. 열이 바뀐 배포 뒤에는 `events` 탭을 비워 제목 줄이 다시 만들어지게 한다.
- 시험 행은 Apps Script 편집기에서 `clearTestRows` 를 골라 실행하면 지워진다. src 열이 `claudetest` 인 행만 지우고, 실행 로그에 지운 행과 남은 행 수가 나온다. 지운 행은 시트의 '파일 > 버전 기록'에서 되살릴 수 있다.
- `events` 탭을 통째로 지우면 `_data` 탭의 수식이 깨진다(#REF!). 지운 뒤에는 `QFlowz > 대시보드 새로 만들기` 를 한 번 더 누른다.
- 대시보드와 `_data` 에는 이름이 없지만 같은 파일 안에 `events` 가 있으니, 대시보드를 밖에 보여 줄 때는 탭을 공유하지 말고 화면을 캡처하거나 값만 복사해 옮긴다.
